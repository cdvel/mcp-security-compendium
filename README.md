## Specification and authorization

Spec security sections, authorization rules and maintainer guidance.

- [Authorization Security Considerations (2026-07-28)](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/security-considerations) by MCP maintainers (Model Context Protocol) · 2026-07-28 · MUST-level security requirements for MCP authorization, covering token audience binding, token theft, mix-up attacks, open redirection, CIMD fetching, localhost redirect URIs and the confused deputy problem. `maintainers` `spec` `T1` `T2` `T9`
- [Security Best Practices (2026-07-28)](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices) by MCP maintainers (Model Context Protocol) · 2026-07-28 · MCP maintainers' catalogue of attacks and mitigations, including confused deputy, token passthrough, SSRF, state handle hijacking, local server compromise, stdio proxy risks and mix-up attacks. `maintainers` `guide` `T1` `T8` `T9`
- [MCP Specification 2026-07-28: Key Changes](https://modelcontextprotocol.io/specification/2026-07-28/changelog) by MCP maintainers (Model Context Protocol) · 2026-07-28 · Changelog for the 2026-07-28 MCP specification, covering removal of protocol sessions and the initialize handshake, issuer validation, and deprecation of Sampling, Roots, Logging and Dynamic Client Registration. `maintainers` `spec` `T1` `T7`
- [OAuth Client ID Metadata Document (draft-ietf-oauth-client-id-metadata-document-02)](https://datatracker.ietf.org/doc/draft-ietf-oauth-client-id-metadata-document/) by Aaron Parecki, Emelia Smith (IETF OAuth WG) · 2026-07-06 · IETF Internet-Draft (not yet an RFC) letting OAuth clients use an HTTPS URL as client_id; listed because the 2026-07-28 MCP spec says clients and authorization servers SHOULD support it. `standards body` `spec` `T1`
- [MCP Authorization Extensions (ext-auth)](https://github.com/modelcontextprotocol/ext-auth) by MCP maintainers (Model Context Protocol) · 2025-10-01 · Official optional MCP authorization extensions, currently Enterprise-Managed Authorization and OAuth Client Credentials, versioned against core protocol revisions. `maintainers` `spec` `T1` `T2`
- [SEP-991: Enable URL-based Client Registration using OAuth Client ID Metadata Documents](https://modelcontextprotocol.io/seps/991-enable-url-based-client-registration-using-oauth-c) by Paul Carleton, Aaron Parecki (Model Context Protocol) · 2025-07-07 · Final MCP enhancement proposal adopting Client ID Metadata Documents for client registration, with its risk analysis (localhost impersonation, SSRF, DDoS) and the case against Dynamic Client Registration, deprecated in 2026-07-28. `maintainers` `spec` `T1`
- [RFC 9728: OAuth 2.0 Protected Resource Metadata](https://datatracker.ietf.org/doc/rfc9728/) by M.B. Jones, P. Hunt, A. Parecki (IETF) · 2025-04 · IETF RFC defining metadata a protected resource publishes to name its authorization servers; listed because the 2026-07-28 MCP spec requires MCP servers to implement it. `standards body` `spec` `T1`
- [RFC 9207: OAuth 2.0 Authorization Server Issuer Identification](https://datatracker.ietf.org/doc/rfc9207/) by K. Meyer zu Selhausen, D. Fett (IETF) · 2022-03 · IETF RFC defining the iss authorization response parameter against mix-up attacks; listed because the 2026-07-28 MCP spec requires clients to apply its issuer validation. `standards body` `spec` `T1`
